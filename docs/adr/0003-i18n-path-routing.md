# 0003. 多言語対応に言語別パス方式を採用する

## ステータス

承認（2026-10-16）

## 背景

- サイトは ja / en / zh（簡体字） / ko の4言語に対応する
- 日本・韓国の担当者が、それぞれの言語で検索・閲覧・共有できる必要がある
- 言語の切り替え方法によって、SEO・hreflang・リンク共有の扱いが大きく変わる

## 決定

- 言語ごとにパスを分ける: `/ja/` `/en/` `/zh/` `/ko/`
  - デフォルト言語の ja にも `/ja/` を付け、全言語を同じ規則にそろえる
  - zh の hreflang は簡体字を明示するため `zh-Hans` とする
- 全ページで hreflang（4言語 + x-default）を出力し、sitemap も言語別に出力する
- ルート（`/`）にアクセスした場合は、次の順で言語を決めて移動する
  1. 保存された言語（localStorage）
  2. ブラウザの言語設定
  3. ja
- JS が無効な環境でも移動できるよう、ルートに各言語へのリンクも表示する

## 検討した代替案

### クエリパラメータ方式（例: `?lang=en`）

- 同じ URL で言語ごとに内容が変わるため、検索エンジンに各言語のページとして認識されにくい
- hreflang で言語ごとのページを示しにくい

### JS で本文を切り替える方式

- 初期 HTML に選択した言語の本文が含まれないため、SEO に不利
- URL が言語を表さないため、リンクを共有すると相手の環境では別の言語で表示される可能性がある

## 結果・トレードオフ

### 利点

- 言語ごとに独立した URL になり、検索エンジンにそれぞれのページとして認識される
- hreflang と sitemap で言語の対応関係を明示できる
- 共有したリンクが、共有した人が見ていた言語のまま開く

### トレードオフ

- 静的サイトではサーバー側で言語を判定できないため、ルートの言語判定は JS で行う。JS が無効な場合に備え、リンクも表示する
- ページを追加するたびに4言語分を用意する必要がある。翻訳キーが欠けている場合はビルド時に型エラーになるよう設計し、漏れを防ぐ
