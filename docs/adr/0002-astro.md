# 0002. フレームワークに Astro を採用する

## ステータス

承認（2026-10-16）

## 背景

- 静的サイトとして構築することを決めた（[ADR 0001](0001-static-site.md)）
- 求める条件は次の3点
  - Lighthouse で各項目 90 点以上を維持できること（特に Performance）
  - 4言語のパス別ルーティングを無理なく実装できること
  - 経歴・プロジェクト紹介といったコンテンツ中心のサイトに向いていること

## 決定

Astro を採用する。

- 標準ではクライアントに JavaScript を出力しない（ゼロ JS）。必要な部分だけ JS を使えるため、Lighthouse のスコアに有利
- i18n ルーティングが組み込まれており、言語別パスを標準機能で実現できる
- Markdown やコンテンツコレクションなど、コンテンツ中心のサイト向けの機能がそろっている

## 検討した代替案

### Next.js（静的エクスポート）

- 実務での採用例が多く、知名度が高い
- しかし静的エクスポートではミドルウェアなどのサーバー機能が使えないため、主な利点を活かせない
- React のランタイムがクライアントに含まれるため、Astro に比べて配信される JS が重い

## 結果・トレードオフ

### 利点

- 初期状態で出力される JS がほぼないため、パフォーマンスを保ちやすい
- 言語別パスやコンテンツ管理を、追加ライブラリなしで実装できる

### トレードオフ

- Next.js に比べると実務での採用例やエコシステムは小さい
- 言語切替のドロップダウンなど、動きのある部分は意識的に JS を追加する必要がある
