# 0005. 操作の多い部品だけに React islands と shadcn/ui を使う

## ステータス

承認（2026-10-17）

## 背景

- デザイン方針を「控えめなモダン」から「モダンでインタラクティブに。ただし性能・アクセシビリティは維持する」に変えた
- サイト自体でフロントエンドの実装力も示したい
- 追加したい機能のうち、Ctrl/⌘+K のコマンドパレット（検索・ダイアログ・キーボード操作）は、アクセシビリティを満たす実装量が多い
  - フォーカスの閉じ込めと復帰、Esc で閉じる、候補の上下移動と読み上げ、背景のスクロール固定 など
- これまでの Lighthouse（モバイル）は全項目 100 で、これを大きく下げたくない（[ADR 0002](0002-astro.md) でゼロ JS を重視して Astro を選んだ）

## 決定

- `@astrojs/react` で React を導入し、**操作の多い部品だけ**を React で作る（いまはコマンドパレットのみ）。ほかは Astro と CSS のまま
- コマンドパレットの UI は shadcn/ui の Command（cmdk）と Dialog（Radix）を使う
  - shadcn/ui はコードをリポジトリにコピーして使う方式なので、サイトの配色変数やタップ領域に合わせて書き換えている
  - `shadcn init` はグローバル CSS に `--muted` `--accent` `--border` などを追加するが、サイトの同名変数と意味が衝突するため使わず、`components.json` を手で用意して `shadcn add` だけを使う
- React は `client:idle` などで読み込まず、**ボタンか Ctrl/⌘+K で初めて開いたときに動的 import する**
  - 初期表示で読み込む JS はトリガー用の約 1.3KB（gzip）だけ。パレット本体（React・cmdk・Radix）約 97KB（gzip）は使う人だけが読み込む
- スクロール登場・hover・スポットライト・ターミナル表示・スキルのバーなどの動きは CSS と小さなスクリプトで作り、`prefers-reduced-motion` を尊重する

## 検討した代替案

### 素の JS（または Web Components）で自作する

- 依存が増えず最も軽い
- ただしダイアログとコンボボックスのアクセシビリティを自前で実装・保守する必要があり、不具合が出やすい

### Preact（preact/compat）

- React 互換で約 4KB と軽い
- Radix・cmdk が互換レイヤーで問題なく動くかを継続的に確認する必要がある。初回オープン時にしか読み込まないため、React との差は体感しにくい

### Motion（旧 Framer Motion）

- アニメーションの表現力は高い
- 今回の動きは CSS（View Transitions・スクロール連動アニメーション・transition）で実現でき、JS を増やす理由がないため使わない

### `client:idle` / `client:visible` での読み込み

- Astro 標準の方法で簡単
- パレットを使わない人にも React の読み込みと初期化のコストがかかる

## 結果・トレードオフ

### 利点

- Lighthouse（モバイル）は主要ページで全項目 100 を維持した（2026-10-17 時点）
- アクセシビリティの難しい部分を、実績のあるライブラリ（Radix・cmdk）に任せられる
- shadcn/ui はコードを所有する方式なので、デザインの変更に合わせて自由に直せる
- React islands を必要な部分だけに絞る設計を、実例として説明できる

### トレードオフ

- 依存が増えた（react / react-dom / @astrojs/react / cmdk / radix-ui / cn）
- 初めてパレットを開くときに約 97KB（gzip）を読み込むため、一瞬待つことがある
- shadcn/ui の部品を追加するたびに、配色クラスをサイトの変数に合わせて直す必要がある
- JS が無効な環境ではパレットを使えない（ボタンを隠し、ナビと言語リンクで代替する）
