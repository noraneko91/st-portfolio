# 0006. 経歴を Projects に移し、「業務経歴」と「個人開発」のタブに分ける

## ステータス

承認（2026-10-18）

## 背景

- これまでは About に経歴の詳細（5件・git log 風タイムライン）があり、About が長く、自己紹介と経歴が混ざっていた
- 伝えたい中心のメッセージは「バックエンド開発から始め、クラウドを含むフルスタックエンジニアへ成長している」ことで、About ではそれを短く伝えたい
- 個人開発は今後も増やしていく。学習で作ったものと自分で企画した制作物が混ざるため、区別して示す必要がある
- 個人開発の情報は、各リポジトリの README・コード・コミット履歴から確認できる事実だけで書く。確認できない点は推測で埋めない

## 決定

- About は「短い自己紹介」と「これから（成長の方向）」に絞り、経歴の詳細は Projects に移す
- Projects を2つのタブに分け、タブごとに URL を持たせる
  - 業務経歴: `/[lang]/projects/work/`（経歴5件と git log 風タイムライン）
  - 個人開発: `/[lang]/projects/personal/`（一覧）と `/[lang]/projects/personal/<slug>/`（詳細）
  - `/[lang]/projects/` は既定のタブである業務経歴へリダイレクトする
  - 旧 URL `/[lang]/projects/st-portfolio/` は新しい詳細ページへリダイレクトする
- タブの見た目はタブだが、中身は URL を切り替えるナビゲーションとして作る（`nav` と `aria-current="page"`。`role="tab"` は同じページ内でパネルを切り替える UI 用なので使わない）。JS がなくても動く
- 個人開発は 1 項目 = 1 YAML とし、分類（学習 / 制作）・状態（進行中 / 完了）・技術（skills 参照）・GitHub・デモ・期間・サムネイルを持つ
  - `npm run new:project <slug>` でひな形を作る
  - 内容が確認できていない項目は `draft: true` で非公開にしておく
  - 概要（overview）がある項目だけ詳細ページを作り、ない項目は一覧から GitHub へ直接リンクする
- fork したリポジトリで本人のコミットがないものは登録しない

## 検討した代替案

### `/[lang]/projects/` に2つのタブの要約を並べる

- 1ページで全体を見渡せる
- ただし各タブの内容と重複し、同じ内容が複数の URL に載る。既定のタブへ移す方が移動も単純なため採用しない

### タブを1ページ内で JS により切り替える

- ページ遷移がなく軽快
- タブごとの URL がなくなり、共有・検索・ブラウザの戻る操作で特定のタブを開けない。JS が無効だと片方しか見られない

### 経歴を About に残したまま、個人開発だけを Projects に置く

- 変更が少ない
- About が長いままで、伝えたいメッセージ（成長の方向）が埋もれる

## 結果・トレードオフ

### 利点

- About が短くなり、成長の方向がはっきり伝わる
- 業務と個人開発を同じ「Projects」の中で並べて見せられる
- 個人開発を YAML の追加だけで増やせ、未確認の内容は公開前に止められる

### トレードオフ

- URL が変わったため、旧 URL のリダイレクトを残す必要がある（Astro の redirects で生成）
- 個人開発で使った技術も skills に登録するため、業務経歴にない技術は年数の代わりに「個人開発」と表示する
- 個人開発の内容はリポジトリの更新に合わせて手で更新する必要がある
