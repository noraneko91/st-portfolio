# 0001. サイトを静的サイトとして構築する

## ステータス

承認（2026-10-16）

## 背景

- サイトの内容は経歴・スキル・プロジェクト紹介で、更新頻度が低く、ユーザーごとに変わる情報もない
- そのため DB やサーバーサイドの処理を必要としない
- 一方で、Python + AWS の実務経験・スキルをどう見せるかを決める必要があった

## 決定

- 静的サイトとして構築し、Cloudflare でホスティングする（GitHub への push で自動デプロイ）
- Python + AWS の技術力は、サイトの構成ではなく Projects ページで個人開発プロジェクトとして紹介する

## 検討した代替案

### AWS 上に直接構築する（S3 + CloudFront など）

- 「サイト自体が AWS の実績になる」という利点を検討した
- しかし静的ホスティングは構成がシンプルで、AWS の実績としてのインパクトは小さい
- それよりも、設計判断や課題解決の過程を説明できる個人開発プロジェクトを Projects ページで見せる方が、技術力が伝わると判断した

## 結果・トレードオフ

### 利点

- コスト: 必要なのは基本的にドメイン費用のみ
- 速度: ビルド済みの HTML を CDN から配信するため表示が速い
- セキュリティ: サーバー・DB がないため、攻撃される箇所が少ない

### トレードオフ

- 動的な機能（フォーム送信など）が必要になった場合は、外部サービスの利用を別途検討する必要がある
- サイト自体からは AWS のスキルが伝わらない。これは Projects ページの内容で補う
